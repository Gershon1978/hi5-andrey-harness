# hi5-andrey-harness вЂ” the Andrey test bench

A **separate** app whose only job is to test **Andrey** (the live bike-mechanic brain at
`https://hi5.bike/Andrey`): run the real two-video flow against the real brain, store every run,
then re-analyse the results (gate calibration, wrong-fit rate, cost, latency).

- **Spec / rationale:** `SPEC.md` (Gemini's answers, verbatim вЂ” the contract for this tool)
- **Brief it was built from:** `TEST_QUESTIONS.md`
- **`examples/`** вЂ” real live-brain response samples (`capture`, `blueprint`, `verdict`) to build against
- **`BUILD_DIRECTIVES.md`** вЂ” the task list for the AI Studio Build agent (ROUND 1 = make it run)
- **Generated by:** Google AI Studio (gemini-3.8-flash), 18 files, extracted from the chat DOM.

## For AI Studio Build
1. **Import from GitHub** в†’ this repo.
2. Set **Secrets** (Settings в†’ Secrets):
   - `ANDREY_BASE` = `https://hi5.bike/Andrey`
   - `ANDREY_TOKEN` = the live `X-Andrey-Token` secret (same value as `ANDREY_API_TOKEN` on the brain).
3. Ask the agent to do **`BUILD_DIRECTIVES.md` в†’ ROUND 1** (make it run, wire the batch, add the
   comparator, add the calibration route).

## Run it

```powershell
npm install
# .env  (server-side only вЂ” never in the browser)
#   ANDREY_BASE=https://hi5.bike/Andrey
#   ANDREY_TOKEN=<the live X-Andrey-Token>
npm run dev        # API on :3001 (Express), UI on :3000 (Vite, proxies /api -> :3001)
```

`ANDREY_TOKEN` is the same secret as `ANDREY_API_TOKEN` in `/root/aim/app/.env` on the brain server.
The proxy injects `X-Andrey-Token` server-side; the browser never sees it.

## What it stores (SQLite: `server/storage/harness.db`)

`runs`: run_id, created_at, tester_name, session_label, adversarial_tag, both file hashes / durations /
bytes, input_symptom, input_model, the **raw** passport/flow/deeper/handoff JSON, derived_gate,
confidence, deeper_rounds_count, causes_summary, diy_price_rub, workshop_price_text, required_parts,
fit_constraints, both latencies, cost_rub_estimated (ledger delta), http_error_code, raw_error_body,
ground_truth_label, ground_truth_job, expert_note, reviewed_at.

Persists across restarts (WAL). Lost on restart: in-flight requests, and the video **blobs** вЂ” by design
only hashes + metadata are kept, so a case is reproducible by its file hash, not by its content.

## Known gaps (found by inspection вЂ” not yet fixed)

0. **`npm install` FAILS on this machine (P0).** `better-sqlite3@11.8.1` has no prebuilt binary for
   **Node v26.3.1** and there is no MSVC toolchain here, so node-gyp dies with
   `npm error gyp ERR! find VS` в†’ `Could not find any Visual Studio installation to use` в†’ `not ok`,
   plus an `npm warn cleanup EPERM вЂ¦ @babel/core/lib` left over from a killed process.
   **Fix (BUILD_DIRECTIVES ROUND 1 #1):** point `server/storage/db.ts` at the built-in
   `node:sqlite` (Node в‰Ґ 22.5, zero native deps). Do **not** install Visual Studio.
1. **`tsc` will fail first time.** `tsconfig.json` sets `noUnusedLocals`/`noUnusedParameters` to `true`;
   several components import icons they do not use (`BatchManager` imports `AlertCircle`, `FileSpreadsheet`;
   `App.tsx` imports `Activity`, `ClipboardList`, `BarChart2`, `Layers`, `ShieldAlert`). Either use them
   or drop them.
2. **BATCH is UI-only.** `BatchManager.handleStart()` just flips a local flag вЂ” it never calls
   `POST /api/harness/batch/start`, and `server/index.ts` has no batch route yet. The manifest is not executed.
3. **No side-by-side comparator.** The spec promises a screen that diffs two `run_id`s (causes, confidence,
   prices). It is not in the delivered files.
4. **No auth on the harness itself.** It is an internal tool with a live token behind it вЂ” put it behind a
   login or bind it to localhost before it is reachable from the network.
5. **`multer@1.4.5-lts.2` is flagged vulnerable** by npm; upgrade to 2.x.
6. **`/api/harness/analytics/calibration` is referenced by the UI** вЂ” confirm the route exists and returns
   the 5 confidence bins the curve expects.
7. The client-side 18 s / 40 MB check warns but does not block, and `RunnerFlow` uses `alert()`.
